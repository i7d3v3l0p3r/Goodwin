# Goodwin on ESP32-S3 N16R8

Goodwin runs on the ESP32-S3 without a Linux host. The `espidf` platform
provides Wi-Fi, NVS and I²S. The `esp32s3-generic` model supplies the pinout and
the supported wake-word runtime. Both platforms use the same Rust voice
pipeline and Solid web panel.

The ESP release includes local activation by «Гудвин» with microWakeWord,
push-to-talk, an OpenAI-compatible provider, text chat, microphone and wake
settings, voice diagnostics, WASM add-ons, and firmware updates through the
panel.

## Wiring

| GPIO | Connection |
| --- | --- |
| 4 | Momentary button to ground, with internal pull-up |
| 5 | I²S BCLK on the microphone and amplifier |
| 15 | I²S WS/LRCLK on the microphone and amplifier |
| 7 | INMP441 SD, with the microphone set to its left slot |
| 6 | MAX98357A DIN |

The adapter uses 16 kHz I²S with 32-bit stereo slots. The cloud receives 16-bit
mono WAV. The provider's 24 kHz mono PCM is resampled to the I²S rate.

Say «Гудвин» and ask a question, or hold the GPIO 4 button while speaking.
Wake activation preserves audio from before detection and ends the recording
after a pause. Recordings are limited to 16 seconds and synthesized replies to
30 seconds. Use **Activation and microphone** to pause wake activation or
adjust the detector and transcription gains. The panel microphone switch also
blocks push-to-talk and voice checks.

In **Activation and microphone**, choose the bundled «Гудвин» microWakeWord
model or a compatible LiveKit Micro INT8 model from Goodwin-wakeword. Goodwin
checks the size and SHA-256 of downloaded models up to 512 KiB and saves the
selected model for future boots. microWakeWord uses an integer cutoff of 249
and averages eight predictions. The sensitivity slider applies to LiveKit models.

## Build

Install the Xtensa Rust toolchain with [espup](https://github.com/esp-rs/espup)
and `ldproxy` with `cargo install ldproxy --locked`. Source the shell file
generated by espup and activate ESP-IDF v5.5.2 with its export script. Set
`ESP_IDF_TOOLS_INSTALL_DIR=fromenv` to use that ESP-IDF installation. The wake
and WASM builds also need Git, Python 3, CMake 3.23 or newer and Ninja.

Run these commands from the repository root.

```sh
npm ci --prefix web
npm run build --prefix web
python scripts/build-esp32s3.py
```

The script builds the pinned TFLite Micro runtime and verifies the SHA-256 of
the [microWakeWord model](https://github.com/i7d3v3l0p3r/Goodwin-wakeword/releases/tag/v0.3.0)
and the legacy LiveKit model. It includes both models in the firmware
and writes the flash images and `SHA256SUMS` to `target/esp32s3/production/`.
Use `--button-only` to compile out the model and wake runtime. Cargo fetches and
builds WAMR Fast for the plugin host. Use `--no-plugins` to omit both. Use
`--emulator` to build for
ESP-EMU. The N16R8 flash and octal PSRAM settings are in `sdkconfig.defaults`.
The layout in `partitions.csv` provides two 4 MiB application slots and a
7 MiB volume for add-ons and downloaded wake models.

## Flash and configure

For a fresh board, flash the merged production image.

```sh
python -m esptool --chip esp32s3 --port /dev/ttyACM0 write_flash \
  --flash_mode dio --flash_size 16MB 0x0 target/esp32s3/production/merged.bin
```

On Windows, use the board's `COM` port in place of `/dev/ttyACM0`.
Open the serial console at 115200 baud. On first boot, Goodwin starts a
password-protected `Goodwin-…` Wi-Fi network and prints its password and setup
address. Join that network, open the printed address and choose whether to use a panel password.
Enter your Wi-Fi network name and password in **Wi-Fi**. Goodwin saves the new
settings after it connects and obtains an address. Switch your browser device
to the same network and open the new address printed on serial. If the new
settings fail, Goodwin restores the previous network or reopens the setup network.

Open **Provider** and enter the URL with its API prefix, such as `/v1`, the
API key and the models for recognition, replies and synthesis. Production
firmware uses HTTPS. The provider must implement `/audio/transcriptions`,
`/chat/completions` and `/audio/speech`. The TTS model and voice must return
24 kHz little-endian PCM for `response_format: "pcm"`. The panel stores the key
in NVS and reports whether a key is configured. Use **Diagnostics** to check
the complete voice path with or without the wake word, inspect the last
request, and read the current boot's protected diagnostic log.
Enable **Streaming playback** to play PCM as it arrives.

## Add-ons

Sign in and upload the same `*-wasm32.tar.gz` packages used on Mini 3 under
**Add-ons**. The ESP build accepts up to four packages with ustar archives
up to 768 KiB each and expanded contents up to 1 MiB. Files and settings
persist in the plugin flash volume. The **Diagnostics** page shows usage
of that volume and the two memory regions.

The metrics export counts mono samples delivered to the wake detector in
`wake_capture_samples`. Compare the count across an interval of continuous
listening at 16 kHz, accounting for wraparound at 2³² samples.
`wake_max_lag_samples` gives the largest distance in
samples between a completed prediction and the latest captured audio since
boot. Divide it by 16 for milliseconds. `capture_skipped_frames` counts the
detector frames skipped to catch up and results discarded when their pre-roll
had already fallen out of the capture history.
Each frame spans 30 ms with microWakeWord or 80 ms with LiveKit Micro INT8.

Timers provides its own page, a local alarm and tools for models that support
tool calling. Wake-word dataset requires a wake-enabled build. Use package
version 0.1.2 or later to capture microWakeWord frames. For OpenAI-compatible, add a named HTTPS
connection in the plugin settings and select it for any of the three stages
in **Settings → Provider**. The built-in provider remains available for the
other stages.

For automated Wi-Fi provisioning, copy `provisioning.example.csv` to the
ignored `provisioning.csv` and fill in the credentials. Keep the CSV and
generated image local. Flashing this NVS image also replaces the saved panel
password, provider and microphone settings.

After upgrading a board with an Argon2 panel password, use this USB
provisioning procedure and then set a new panel password. Saved PBKDF2
passwords continue to work. You can enable or disable the password in
**Settings → Panel**. Updates, add-on management and logs require a password.
Sign-in sessions last up to 30 days while the board remains running.

```sh
python "$IDF_PATH/components/nvs_flash/nvs_partition_generator/nvs_partition_gen.py" generate \
  firmware/esp32s3/provisioning.csv target/esp32s3/goodwin-nvs.bin 0x6000
python -m esptool --chip esp32s3 --port /dev/ttyACM0 write_flash \
  0x9000 target/esp32s3/goodwin-nvs.bin
```

## Update

Sign in to the panel, open **Settings → Core updates**, and upload `app.bin`
from the matching firmware build. ESP-IDF validates the image and selects the
other application slot. Goodwin confirms the new firmware after startup checks.
Wi-Fi, panel credentials and provider settings stay in the NVS partition.
Installed plugins, their data and the selected wake model persist across OTA
updates.

The earlier ESP preview images used 3 MiB slots and did not have a plugin
volume. Moving from that layout requires the new partition table and a
fresh flash from `merged.bin`. Back up NVS settings before flashing a
previously configured board.
[ESP-IDF OTA and rollback](https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32s3/api-reference/system/ota.html)

## Test with ESP-EMU

Build the emulator variant and run the integration test. Use the matching
[ESP-EMU 1.2.0 examples](https://github.com/espressif/esp-emulator/releases/tag/v1.2.0)
for the I²S microphone, amplifier and button parts.

```sh
python scripts/build-esp32s3.py --emulator
python firmware/esp32s3/test_emulator.py \
  --firmware target/esp32s3/emulator/merged.bin \
  --examples /path/to/esp-emu-1.2.0-examples \
  --work target/esp32s3/smoke --wake-build --provision-wifi \
  --update-image target/esp32s3/emulator/app.bin --stream-speech
```

The emulator test uses a local provider fixture and checks password setup,
chat, the requested audio formats, voice report timings, memory usage and an
audible response. With `--provision-wifi` it also tests a failed Wi-Fi attempt
before switching to the working network. For wake activation, pass
`--wake-audio /path/to/request.wav` with a mono 16-bit, 16 kHz recording of
«Гудвин» followed by a question and silence.
Pair it with `--wake-test` to check activation while continuous listening is
paused.
Add `--wake-catalog-model /path/to/goodwin-micro-int8.tflite` to test catalog
filtering, checksum validation, live model replacement and persistence.
Add `--interrupt-update` to reset the device before OTA verification and check
that it starts the previous firmware.

The Linux pull request checks build this firmware with ESP-IDF v5.5.2 and
Xtensa Rust 1.97.0.0. They run ESP-EMU 1.2.0 against the panel contract,
the installed wake model, streaming speech, Timers and the Wake-word dataset storage quota.
Use `--emulator-timeout` to allow more wall-clock time on a slower runner.

Use the packages from `python scripts/build-wasm-plugins.py` to exercise the
plugin host in the same run. Pass `--timers-package` with the Timers archive and
`--timer-voice-tool` to test a tool call. Pass `--dataset-package` to check the
storage quota across a restart, and add `--wake-audio` to record a detector clip.
Pass `--provider-package` to configure
the OpenAI-compatible guest and use it for the text and voice requests.
